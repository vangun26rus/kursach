0497: 4 Программная реализация информационной системы
0498: 4.1 Обзор инструментальных средств разработки
0499: Для разработки информационной системы был выбран Visual Studio Code (VSCode) — это мощный редактор кода от Microsoft. Он сочетает в себе простоту текстового редактора с функциональностью полноценной IDE, включая глубокую интеграцию с современными веб-технологиями, поддержку встроенного терминала и обширную экосистему расширений [1].
0500: В качестве основного фреймворка для построения пользовательского интерфейса используется React 18, который обеспечивает высокую производительность благодаря конкурентному рендерингу и автоматической пакетной обработке обновлений состояния. Для управления состоянием приложения применяется Redux Toolkit — современный подход к Redux, устраняющий избыточный код и предоставляющий встроенные инструменты для работы с иммутабельностью и API-запросами (RTK Query). Маршрутизация реализована с помощью React Router v6, поддерживающего ленивую загрузку компонентов и защищённые роуты [2,9].
0501: Серверная логика построена на Express.js — минималистичном, но производительном фреймворке для Node.js, способном обрабатывать до 30 000 запросов в секунду. В качестве базы данных выбрана PostgreSQL — надежная реляционная СУБД с поддержкой JSON, оконных функций и строгой транзакционной целостностью. Для удобной работы с данными используется Sequelize ORM, предоставляющий продвинутые возможности, такие как полиморфные ассоциации и мягкое удаление записей [4].
0502: Система аутентификации реализована на основе сессионного механизма (Session-based) с использованием express-session. Данные сессии хранятся на сервере, что обеспечивает высокий уровень контроля и безопасности. Для защиты от атак применяются:
0503: HttpOnly-куки — предотвращают кражу сессии через XSS-атаки
0504: SameSite=Strict — защита от CSRF
0505: Двойная подпись сессии — дополнительная верификация данных
0506: Для управления правами пользователей используется ролевая модель (RBAC), интегрированная с системой сессий.
0507: Дополнительные технологии:
0508: Chart.js с WebGL-ускорением для визуализации данных
0509: React Bootstrap 5 с адаптивной grid-системой
0510: Nodemailer для транзакционных email-уведомлений
0511: Dotenv для управления конфигурацией среды
0512: Для задачи генерации изображений тортов по текстовому описанию была выбрана архитектура диффузионных моделей (Diffusion Models), в частности Stable Diffusion [13], по следующим причинам:
0513: Качество генерации: Современные диффузионные модели демонстрируют превосходное качество генерации изображений по сравнению с другими подходами (GAN, VAE), особенно в задачах, требующих детализации и точного соответствия текстовому описанию.
0514: Стабильность обучения: В отличие от GAN, где часто возникают проблемы с режимом коллапса и нестабильностью обучения, диффузионные модели обучаются более предсказуемо.
0515: Гибкость управления: Diffusion Models позволяют точно контролировать процесс генерации через текстовые промпты, что критически важно для задачи создания кастомизируемых дизайнов тортов.
0516: Эффективность: Stable Diffusion использует латентное пространство для диффузионного процесса, что делает модель более эффективной по сравнению с подходами, работающими непосредственно в пространстве пикселей.

0555: Выбор базовой модели
0556: В качестве базовой модели был выбран Stable Diffusion v1.5 по следующим причинам:
0557: Проверенная архитектура с хорошим балансом качества и производительности
0558: Широкая поддержка сообщества и документация
0559: Оптимизированная работа с текстовыми промптами
0560: Поддержка механизма LoRA для эффективного дообучения
0561: Адаптация модели для предметной области
0562: Для адаптации модели к задаче генерации дизайнов тортов были выполнены следующие шаги:
0563: Добавление LoRA-слоев: Реализована модификация архитектуры UNet с добавлением Low-Rank Adaptation (LoRA) слоев, что позволяет эффективно дообучать модель на ограниченном наборе данных без риска катастрофического забывания.
0564: Подготовка датасета: Создан специализированный датасет с изображениями тортов и их текстовыми описаниями, включающими:
0565: Количество ярусов
0566: Форму торта
0567: Тип покрытия
0568: Элементы декора
0569: Наличие фигурок
0570: Фоновое оформление
0571: Модификация процесса обучения:
0572: Использование mixed-precision training для оптимизации использования памяти
0573: Реализация gradient checkpointing для работы с большими batch sizes
0574: Интеграция с Weights & Biases для мониторинга обучения
0575: Этот технологический стек используется в высоконагруженных системах и соответствует лучшим практикам enterprise-разработки. Каждый компонент был выбран после тщательного анализа альтернатив.

0578: 4.2.1 Алгоритм создания заказа с конструктором тортов
0579: Алгоритм создания заказа с конструктором тортов является частью ключевого алгоритма всей системы кондитерской, подробную схему самого алгоритма можно наблюдать на рисунке 4.1.
0580: Инициализация процесса начинается с перехода пользователя в раздел «Конструктор тортов». Код процесса создания изображен на рисунке 4.2.
0581: В конструкторе реализован пошаговый процесс:
0582: 1) Выбор параметров торта (начинка, покрытие, декор и другие характеристики).
0583: 2) Генерация визуального представления с использованием ИИ-технологий:
0584: При неудовлетворительном результате пользователь может повторно запустить процесс генерации. При получении удовлетворительного изображения предусмотрена возможность добавления текстовых пожеланий.
0585: 3) Добавление сформированного торта в корзину с предварительной проверкой авторизации аналогично стандартным товарам.
0586: Процесс оформления заказа происходит следующим образом. После добавления персонального торта при возврате в корзину система анализирует возможность применения скидочных промокодов при наличии действительного промокода выполняется перерасчет итоговой суммы, логику расчета можно просмотреть на рисунке 4.2.

0608: 4.2.3 Алгоритм работы каталога с динамической каруселью
0609: Алгоритм работы каталога с динамической каруселью является современным подходом к представлению товаров в интернет-магазинах, подробную схему самого алгоритма можно наблюдать на рисунке 4.5.
0610: Пользователь открывает раздел «Каталог» с выбором категорий товаров, где подгружаются все категории и все подробности уникальных дизайнов вместе с ними. Загрузка идет в общем компоненте каталога, который можно посмотреть на рисунке 4.6.
0611: В данном компоненте реализована интерактивная карусель категорий с циклической навигацией, позволяющая бесконечно перебирать элементы как в прямом, так и в обратном направлении. Визуально карусель состоит из трех позиций: центральной активной категории, которая стилистически выделена для привлечения внимания пользователя, а также двух соседних элементов (предыдущего и следующего), которые частично скрыты (применена 50% прозрачность) и имеют эффект размытия для создания визуальной иерархии и акцента на активном содержимом.

Логика работы компонента, включая механизм циклической смены элементов и обработку пользовательских взаимодействий, представлена на рисунке 4.7. Данная реализация обеспечивает интуитивно понятный интерфейс навигации по категориям с четкой визуальной индикацией текущего положения, что способствует улучшению пользовательского опыта взаимодействия с системой.

0616: Рисунок 4.7 – Логика смены категорий
0617: Архитектура компонента предусматривает неограниченное расширение количества товаров в категории. Каждый товар в карусели обладает уникальным набором стилевых характеристик и информационным наполнением, хранящимся в базе данных (как показано на рисунке 4.8). При переключении между элементами карусели происходит динамическое обновление интерфейса: меняется дизайн карточки товара и отображаемая информация, при этом система обеспечивает плавность переходов и визуальную согласованность. Реализованное решение позволяет эффективно представить товарный ассортимент, обеспечивая пользователю удобный механизм просмотра и выбора продукции с сохранением целостности восприятия информации.
0618: Рисунок 4.8 – Логика динамической карусели товаров
0619: В интерфейсе реализован оригинальный способ отображения товаров, имитирующий движение конвейерной ленты. Система показывает четыре товара одновременно, размещая их на разных уровнях для создания эффекта глубины. Активный товар выделен в центре увеличенным размером. Следующий товар расположен ниже и левее, он меньше по размеру и слегка размыт. Еще дальше находится третий товар - самый маленький и полупрозрачный. Четвертый, предыдущий товар, плавно уходит вверх. Такое расположение создает динамичный эффект движения, где товары последовательно проходят через все позиции: от пред просмотра через активное состояние до завершения цикла. Подобная визуализация улучшает восприятие каталога и делает интерфейс более интерактивным. Для реализации использованы CSS-анимации и точная настройка переходов между состояниями.
